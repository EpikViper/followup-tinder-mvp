Workflow 01 / event path

One Unipile message arrives

The live path filters the event, resolves one Attio person and their linked company, checks Outbound Pipeline membership, then updates identity, activity, transcript, counters, and alerts.

Active · 42 implementation nodes
TriggerEvery message event
Identity priorityURN, then exact name
Company sourcePerson's linked company
Write gateOutbound Pipeline
!
"Deduplicated" means the message ID was seen, not that the Attio contact was deduplicated.

The live workflow records the ID in n8n static memory before any Attio write succeeds. That is an at-most-once gate, not a durable completed-write ledger.

01

Admit or drop the event

Unipile webhook

The event is allowed only if every guard below passes.

EventMust be message_received.
Networkaccount_type must be LinkedIn.
MailboxOnly Sandro, Sergi, or Revaz account IDs.
ConversationNot a group; no more than 2 attendees.

Direction and counterpart
DirectionUse is_sender; otherwise compare sender provider ID with the mailbox's own LinkedIn ID.
No counterpart URNDrop the event. No Attio lookup, note, date, or alert is written.
02

Build the contact candidates

Unipile + Attio

One Attio query uses an OR across a stable identifier and exact full-name variants.

Name variant ACollapse repeated whitespace in the Unipile display name.
Name variant BKeep the raw name, including its original whitespace.
Name variant CStrip pictographs/symbols and trim non-alphanumeric edges.
Attio query: linkedin_urn = counterpart URN OR name.full_name = any exact variant · limit 25
Exactly 1 URN resultChoose it. Name results are ignored.
2+ URN resultsAmbiguous duplicate records. Write nothing and prepare an inbound-only Slack alert.
0 URN + exactly 1 exact-name resultChoose it, even without email, domain, employer, or profile URL corroboration.
0 URN + 2+ exact-name resultsAmbiguous. The live path does not use pipeline membership to break the tie.
03

Accept the person's company

Attio relation

The chosen person's first linked company target becomes the company for the entire message and transcript.

Person + linked companyContinue. The company gets last_interaction_by immediately.
Person but no companyNo transcript, no URN cache, no pipeline update. Inbound alert once per 24 hours.
No person + inboundWait 15 minutes for SendPilot, then rerun the same Attio person query.
No person + outboundThe workflow checks whether the thread ever had an inbound message, but both outcomes are silent because the final alert gate only allows inbound events.
15-minute recheck finds a rowThe run ends in "Silent Skip"; it does not re-enter matching or log this original message.
15-minute recheck still emptyInbound gets a Slack card with buttons to create the lead at a chosen stage.
Company identityNo company-name or domain matching occurs in this workflow.
04

Require an Outbound Pipeline entry

Attio list

The system fetches every entry attached to the company and takes the first whose list API slug is cold_calling.

Entry existsFetch that entry and continue to CRM writes.
No entryNo URN cache, transcript, counter, or date update. Inbound gets a rate-limited Slack alert.
Partial write before this gatelast_interaction_by was already patched on the company when person + company matched.
Multiple matching entriesThe first cold_calling entry returned by Attio wins.

Write the matched conversation

Attio + Slack

Once the company is on the pipeline, these writes run from the selected person/company/chat identity.

Cache identity

Patch the company to "Us" for outbound and "Them" for inbound. This occurs before pipeline membership is known.

Workflow 02 / reconciliation path

Rebuild recent and historical chats

The reconciler covers messages the webhook missed and threads that only became matchable after an Attio person was created. Its duplicate-contact behavior is different from the live path.

01

Select one-to-one chats for three mailboxes

Schedule + Unipile

Each mailbox is queried separately. A chat proceeds only if it is type 0 (one-to-one), has a counterpart provider ID, belongs to one of the configured accounts, and falls inside the time window.

Daily overlap26 hours intentionally overlaps runs so a late or missed run can be recovered.
Weekly sweepCurrent configuration scans the last 92 days.
PaginationUp to 40 pages of 100 chats per account.
02

Match the Attio person using the same ladder

Attio people

URN is preferred; exact full-name variants are the fallback. Unlike the live path, duplicate candidates are expanded and tested against the pipeline.

One person + companyContinue with that person's linked company.
2+ matching peopleKeep only candidates that have a linked company, then inspect each company's list membership.
No person or no linked companyNothing to sync. No create-person path exists here.
Counterpart has no display nameThe chat is unusable and stops before Attio lookup.
03

Resolve duplicate people by pipeline membership

Current tie-breaker

For ambiguous URN or exact-name matches, candidates are expanded. Only candidates that first pass the note-based "Needs Sync" gate reach the company pipeline check.

Exactly 1 surviving candidate company is on cold_callingThat person's record wins and the chat is synced. Slack still reports the original duplicate set.
0 surviving candidate companies are on the pipelineWrite nothing and alert.
2+ surviving candidate companies are on the pipelineWrite nothing and alert. There is no next tie-breaker.
This is selection, not deduplicationNo people or companies are merged and no duplicate record is removed.
04

Skip stable historical notes; rebuild active ones

Note map

The company field linkedin_note_id is treated as a JSON map from Unipile chat ID to Attio note ID.

No map entry for this chatSync the chat.
Chat active in the last 4 daysSync again even when a note ID exists.
Map entry exists + no activity for 4 daysMark "Already Synced" and do nothing.
Legacy bare note IDParsing fails; the map is treated as empty, so the chat is rebuilt.
05

Derive CRM state from the full thread

Reconciliation writes

Latest interaction date

Use the newest message of either direction. Only move the stored date forward.

Last interaction by

Use the direction of the newest message: "Us" or "Them".

Follow-up count

Count every consecutive us-to-us message pair on different Tbilisi days across the full thread.

Counter overwrite rule

Only backfill the derived count when Attio's current value is missing or zero. A nonzero value is preserved even if wrong.

Identity cache

Write the counterpart URN onto the selected Attio person.

Transcript note

Create the replacement note, delete the old chat note, then group note-map updates into one company patch.

The daily and weekly triggers feed the same reconciliation logic. The weekly 92-day range is an editable slice in the current code.

Workflow 03 / exact rules

What "matching" and "dedupe" mean today

This is the shortest operational reference: which key is used, what counts as a collision, and what the system does next.

Current behavior
1

Normalize the Unipile display name

Create raw, whitespace-collapsed, and decoration-stripped variants.

No fuzzy, token, nickname, email, or domain matching.
2

Query Attio with one OR filter

linkedin_urn = provider ID OR name.full_name = exact variant. Limit 25.

The query can return URN and name candidates together.
3

Prefer the URN result set

Exactly one URN match wins. Two or more is considered duplicate-person ambiguity.

A unique URN match ignores any conflicting name candidates.
4

Fallback to exact full name

Only when no URN result exists. Exactly one normalized exact-name match wins.

No independent evidence is required for this fallback.

Live stops. Reconciler chooses only if exactly one candidate's linked company is on the Outbound Pipeline.

Duplicates remain in Attio either way.

Workflow 04 / current breakpoints

Where the current behavior can produce the wrong outcome

These are implementation-observed risks from the active workflows, not hypothetical nodes or proposed redesigns.

Needs handling
01

A failed write can be permanently "deduped"

The webhook adds message_id to the seen list before Attio, Slack, or note writes finish. A redelivery after downstream failure is dropped as a duplicate.

Effect: silent missing or partially written interactions.
02

The delivery ledger is a volatile rolling list

Only the last 2,000 IDs are retained in n8n static data. It is not a durable table with processing status, timestamps, attempts, or completed side effects.

Effect: old redeliveries can run again; incomplete runs cannot be distinguished from complete runs.
03

Exact name alone can select a person

When the URN is absent, one exact normalized full-name result wins without checking email, LinkedIn URL, employer, domain, or the message participant's profile.

Effect: a unique but wrong same-name record can receive the transcript and activity.
04

Live and nightly resolve duplicates differently

The webhook rejects every multi-person match. The reconciler can choose one duplicate based solely on whether exactly one candidate's company is on the Outbound Pipeline.

Effect: the same chat can be rejected live but attributed later by a different rule.
05

The 15-minute "found" branch does not sync

If a missing inbound person appears during the wait, the recheck only sees that the query returned a row and ends at Silent Skip. It never resolves the row or logs the triggering message.

Effect: the original inbound depends on a later reconciler run.
06

Company choice is not matched

The person's linked company relation is accepted as truth. The workflow does not verify it against LinkedIn occupation, company name, domain, or any second relation.

Effect: a correct person with a stale company relation writes to the wrong account.
07

The workflow can leave partial state

last_interaction_by is patched before Outbound Pipeline membership. Note replacement also spans create, delete, and map-patch calls without a transaction.

Effect: company activity can change when the rest is skipped; note/map state can diverge on mid-run failure.
08

"Duplicate handling" never repairs duplicates

Candidate records are summarized in Slack, but the automations do not merge people, consolidate URNs, choose a canonical record persistently, or migrate relationships.

Effect: the same ambiguity recurs until a human changes Attio.
09

Note state filters candidates before duplicate resolution

In the reconciler, an ambiguous candidate with an existing, inactive note map is removed by "Already Synced" before pipeline membership is compared. The resolver only sees the candidates that still need a note sync.

Effect: the duplicate tie-breaker does not always compare the full candidate set.
→
The highest-leverage fix area is identity + idempotency, before field writes.

A durable event ledger, explicit match evidence, one canonical contact decision, and a resumable write state would remove several of these failure modes together.
